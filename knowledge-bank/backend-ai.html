Execution Engine: FastAPI + Discord + LLM Router

This page combines Discord setup, backend APIs, tool execution safety, RAG, confidence control, and autonomous moderation mechanics.

Discord Setup Quick Path

  1. Create app + bot in Developer Portal
  2. Enable required OAuth scopes
  3. Enable minimum required intents
  4. Register slash commands + bot install flow
  5. Persist per-tenant bot credentials encrypted

FastAPI Module Design

api/, domain/, infra/, and workers/. Keep policy and execution layers separate to guarantee predictable safety gates.

Essential Endpoints

  • POST /chat/messages
  • POST /actions/confirm
  • POST /channels/bulk-create
  • POST /moderation/user/sanction
  • GET /analytics/moderation-summary

Prompt To Action Lifecycle

1) Parse Intent classification + candidate tools.
2) Constrain Enforce tool schema + policy boundaries.
3) Assess Compute risk + confidence score.
4) Confirm Ask user for approval on risky operations.
5) Execute Run Discord action adapter with idempotency.
6) Audit Persist full decision trace and execution receipt.

Confidence Policy

High confidence (>=0.90): execute safe actions.

Medium confidence (0.75-0.89): ask clarification/confirmation.

Low confidence (<0.75): block execution and rephrase prompt.

RAG Design

  • Tenant-isolated knowledge index
  • Owner-controlled document ingestion
  • Citation for behavior and policy answers
  • Refresh controls and freshness metadata

Autonomy Mode Controls

  • Action whitelist by risk tier
  • Protected users/channels/roles
  • Rate caps per min/hour/day
  • Immediate kill switch

Spring Boot Integration (Later)

Extract policy engine when rule complexity grows. Keep FastAPI as orchestrator, and call Spring Boot for policy evaluation through versioned contracts.
